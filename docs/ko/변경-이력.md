# 변경 이력

이 문서는 CodexManager의 외부에 보이는 변경 사항을 기록하는 버전 이력의 단일 기준 문서입니다.
형식은 Keep a Changelog를 참고하되 현재 저장소 운영 방식에 맞게 가볍게 조정했습니다.

## [Unreleased]

## [0.6.3] - 2026-09-30

### Added

- 모델 카탈로그 revision 10에 내장 `gpt-6.1-sol`을 추가하고 공식 설명, reasoning 단계, 단/장 컨텍스트의 입력·캐시 입력·캐시 쓰기·출력 가격을 반영했습니다. custom 모델, 사용자 수정과 삭제 tombstone은 보존합니다.

### Changed

- 데스크톱 탐색, 설정, 대시보드, 플랫폼 모드와 모델 관리 화면을 더 조밀하게 정리하고 지원 언어의 상태 표현을 맞췄습니다.

### Fixed

- 스트리밍 최종 이벤트 전달 추적과 bridge 진단 로그를 개선해 클라이언트에 최종 이벤트가 전달된 경우와 upstream 미완료·클라이언트 전달 실패를 구분합니다.

## [0.6.2] - 2026-09-25

### Added

- 모델 카탈로그 revision 9에 `gpt-6-sol`, `gpt-6-luna`, `gpt-image-2.5-sunburst`, `gpt-image-2.5-flare`를 추가했습니다. fresh 카탈로그는 이제 기본 표시 모델 10개와 숨겨진 `codex-auto-review`를 합쳐 builtin 11개를 포함합니다.

### Changed

- 2026-08-31에 ChatGPT 로그인 방식의 Codex에서 retired된 `gpt-5.4`, `gpt-5.4-mini`와 해당 로그인 경로에서 deprecated된 `gpt-5.2` builtin을 제거했습니다. 일반 API Key 사용은 custom 모델을 통해 계속 지원됩니다. revision 9는 수정되지 않은 builtin과 기본 account-pool route를 삭제하지만, 사용자 편집, custom 가격 또는 tier, 기본값이 아닌 route, permission/API Key 연결은 custom 모델로 전환해 보존합니다.
- free-account 모델 상한 선택지는 현재 텍스트 모델 카탈로그를 기준으로 다시 구성합니다. 현재 후보 카탈로그에 더 이상 포함되지 않는 값, 이미지 전용 값 또는 오래된 fallback 값은 `auto`로 정규화합니다. 계정 warmup과 계정 텍스트 테스트의 fallback은 `gpt-6-luna`로, observation bridge의 기본 모델은 모델이 없을 때 `gpt-6-sol`로 변경했습니다.
- 릴리스 버전을 `0.6.2`로 올리고 workspace, frontend, Tauri desktop metadata 및 lock file을 동기화했습니다.

### Fixed

- 데스크톱 개발 실행에서 pnpm 명령 해석과 Next 프록시 시작 경쟁을 수정했습니다. 숨겨진 페이지는 페이지 단위 polling과 백그라운드 작업을 중지하고, account-test와 SSE listener는 종료 상태에서 정리됩니다.
- service, gateway, account 및 usage 경로의 리소스 수명, 요청 취소, queue metric과 동시성 경계를 수정해 production 경로에 남아 있던 legacy synchronous bridge 사용을 줄였습니다.
- SQLite 모델 카탈로그 자동 마이그레이션을 강화했습니다. migration lock, online backup, preflight 검사, 대소문자 충돌 slug 처리와 마이그레이션 후 smoke check를 추가했으며, 실패하면 backup에서 데이터베이스를 복원합니다.
- GHCR Release Compose에 선택 가능한 Docker OTA profile을 추가했습니다. 기본 checker는 사용자 승인을 기다리고, 명시적으로 `ota-auto`를 활성화한 경우에만 service/web 이미지를 자동 업데이트하며 고정 버전 tag는 유지됩니다.

## [0.6.1] - 2026-09-24

### Added

- OpenAI 계정 풀에 기본 활성화된 quota reset warmup을 추가했습니다. 5시간 quota가 소진되면 기록된 reset 시각에 짧은 warmup 메시지를 보내고 usage를 새로 고치며, 계정별/일괄 설정과 주기별 시도 기록을 저장하고 비활성 계정 또는 아직 회복되지 않은 주간 quota는 건너뜁니다.
- Codex에 aggregate API direct mode를 추가했습니다. 활성 Codex 또는 Compatible Responses API-key 항목을 선택하고 기존 인증 header와 User-Agent를 그대로 사용하여 local gateway를 거치지 않고 연결할 수 있습니다(#475).

### Changed

- 비동기 service 및 SeaORM storage migration의 production hardening을 마무리하고 remote account, aggregate API, API key, usage, log 및 gateway 경로의 transaction, shutdown, acceptance gate를 보강했습니다.
- 모델 status card 스타일을 통일했습니다. 아무 모델도 선택하지 않으면 전체 카탈로그를 적용하고, 선택 항목이 있으면 해당 모델만 적용하며 가격과 catalog metadata도 동기화합니다.
- 가격 동기화는 모델을 선택하지 않으면 사용자 지정 가격을 유지하고, 명시적으로 선택한 모델에 대해서는 외부 가격이 사용자 지정 가격을 덮어쓸 수 있도록 변경했습니다. 선택하지 않은 사용자 지정 모델은 건드리지 않습니다.
- 모델 삭제는 실제 record 삭제로 변경했습니다. 삭제된 builtin 모델에는 tombstone을 기록하여 startup seed가 다시 복원하지 않도록 했습니다.
- workspace, frontend, Tauri desktop metadata 및 lock file 버전을 `0.6.1`로 올렸습니다.

### Fixed

- Windows client가 연결을 끊었을 때 성공한 aggregate API 응답이 502로 기록되던 문제를 수정했습니다. downstream `os error 10053/10054/10058`은 client disconnect로 처리합니다(#479).
- 비동기 service migration 이후의 account, aggregate API, quota reset 및 candidate routing 경계 문제를 수정하고 transaction rollback과 production configuration 검증을 강화했습니다.

## [0.5.7] - 2026-09-05

### Added

- 기본 모델 카탈로그에 `gpt-6-astra`를 추가했습니다. revision 8 데이터 마이그레이션은 신규 및 기존 데이터베이스에 공식 API 제한과 cache-write 가격, Codex runtime metadata 및 기본 account-pool route를 반영하면서, 동일 slug의 custom 모델과 사용자가 수정한 builtin은 보존합니다.
- 계정 페이지에 선택을 기억하는 표/카드 보기 전환을 추가했습니다. 관리자는 명시적으로 선택한 ChatGPT 계정의 credential, account identifier 및 proxy로 upstream 모델을 가져온 뒤, account-pool rotation 없이 model catalog V2의 account-pool route에 선택적으로 연결할 수 있습니다.
- Responses HTTP, WebSocket 및 request log 전반에 Standard와 Ultrafast API key service tier를 추가했습니다. Standard는 upstream 기본 속도를 사용하고 `standard`로 기록되며, Fast는 `priority`로 변환되고 Ultrafast는 그대로 전달됩니다. 호환성을 위해 Flex도 계속 허용하며 실제 사용 가능 여부는 모델과 upstream에 따라 달라집니다.
- Gateway outbound `User-Agent` 설정을 추가했습니다. `gateway.user_agent`는 전역으로 적용되고, aggregate route 전달·model discovery·probe·balance 요청에서는 연결별 `aggregate_apis.user_agent`가 우선합니다. 두 값이 모두 없으면 동적으로 생성한 Codex-compatible `User-Agent`를 사용합니다(#459).

### Changed

- 릴리스 버전을 `0.5.7`로 올리고 workspace, frontend package, Tauri desktop metadata 및 lock file을 동기화했습니다.

### Fixed

- Responses WebSocket tool output 이어가기를 수정했습니다. 동일한 tool call의 중복 output은 upstream 전달 전에 제거되고, connection preamble event가 terminal recovery 기회를 소모하지 않으며, task 경계를 넘을 때 누락된 tool-call context를 제한된 범위에서 복원할 수 있습니다(#458).
- 후속 새로 고침이나 일시적인 빈 목록 응답 뒤 계정 페이지에서 Luna Reserve 사용량이 사라지는 문제를 수정하고, 추가 할당량의 snake_case 및 camelCase 응답 형식을 모두 일관되게 처리하도록 했습니다.
- Luna Reserve 라우팅 경계를 수정했습니다. 사용 가능한 Reserve 할당량이 있는 계정은 명시적으로 `gpt-reserve`를 요청한 경우에만 Reserve 후보 풀에 들어갑니다. 일반 `gpt-5.6-luna` 요청은 계속 일반 계정 풀을 사용하며 Reserve가 남아 있다는 이유만으로 소진된 기본 5시간/7일 창을 우회하지 않습니다. 강제 인증 또는 비활성화 상태는 기존 규칙대로 처리됩니다.

## [0.5.6] - 2026-09-02

### Added

- 실제 upstream에 text 또는 image model 요청을 보내는 관리자 전용 **계정 테스트** 기능을 추가했습니다. 추측할 수 없는 `testId`로 격리된 Tauri event 또는 Web SSE를 통해 진행 상황, 결과와 취소 상태를 전달하며, `status + updated_at` CAS로 계정 상태를 기록해 이전 테스트가 최신 상태를 덮어쓰지 못하도록 했습니다. `banned`, `disabled`, `inactive` 계정은 자동 복구하지 않습니다(#452).
- **혼합 rotation(aggregate API 우선)** 전략을 추가했습니다. aggregate API를 먼저 시도하고 모든 후보가 요청을 소비하지 않은 채 실패한 경우에만 계정 pool로 안전하게 fallback하며, aggregate-only 모델은 연결된 route를 우회하지 않습니다(#454).
- aggregate API에서 upstream 모델을 가져와 model catalog V2 route에 선택적으로 연결하는 기능을 추가했습니다. 기존 source table이나 자동 연결 pipeline은 복원하지 않습니다.

### Changed

- 릴리스 버전을 `0.5.6`으로 올리고 workspace, frontend package, Tauri desktop metadata 및 lock file을 동기화했습니다.
- platform key, protocol 및 model별로 `prompt_cache_key` 또는 root session ID를 분리하고 동시 cold start를 원자적으로 하나의 binding에 수렴하도록 prompt-cache/cache-affinity routing을 개선했습니다. parent/child 및 streaming 요청이 같은 계정을 안정적으로 재사용하고 성공적인 failover 후에만 다시 binding하며, 관리자 dashboard에 cache hit rate를 추가했습니다.

### Fixed

- 엄격한 client 검증을 사용하는 공급자의 aggregate API 연결 테스트가 잘못 실패하던 문제를 수정했습니다. probe는 기본적으로 공식 Codex client identity를 재현하고 설정된 custom `User-Agent`도 지원하며, 일반 route 전달에는 영향을 주지 않습니다(#451).
- Codex Device Code 로그인 lifecycle, 취소와 browser callback 경쟁을 수정하고 managed gateway profile의 인증 및 WebSocket capability를 동기화했습니다.
- native Codex image-generation 요청의 감지와 routing을 수정했습니다. extension 요청은 필요한 identity header를 유지한 채 Codex image endpoint로 전달되고, 일반 OpenAI-compatible client는 기존 compatibility adapter 경로를 계속 사용합니다.
- desktop updater가 설치 대기 중인 release와 updater log는 보존하면서 완료되었거나 오래된 release directory를 정리하도록 수정했습니다.

- 일부 비성공 upstream 응답의 계정 failover와 default model-group routing semantics를 수정했습니다.

- 修复设置页保存上游代理、平台密钥创建弹窗关闭与重复提交、登录成功后账号表格未刷新等桌面交互问题。
- 修复模型拉取默认附加版本参数导致的部分上游兼容性问题，模型请求改为默认不附带版本号。
- 修复账号导入与登录回调两条链路的账号归并逻辑不一致问题，统一按同一身份规则新增或更新账号。
- 修复 Claude / Anthropic `/v1/messages` 适配在多 MCP server 场景下的工具截断问题；不再因前 16 个工具占满而丢失后续 server 的工具。
- 修复 Claude / Anthropic `/v1/messages` 链路缺少长工具名缩短与响应还原的问题，避免 MCP 工具名过长时映射不稳定。

### Changed
- 网关失败响应增加结构化 `errorCode` / `errorDetail` 字段，并同步补充 `X-CodexManager-Error-Code`、`X-CodexManager-Trace-Id` 响应头，便于客户端与日志系统追踪失败链路。
- 协议适配继续对齐 Codex / OpenAI 兼容生态：进一步统一 `/v1/chat/completions`、`/v1/responses`、Claude `/v1/messages` 的转发语义，并稳固 `tools` / `tool_calls`、thinking / reasoning、流式桥接和响应还原链路。
- 设置页与运行时配置继续收敛：背景任务、网关传输、上游代理、Web 安全等高频配置统一由 `app_settings` 持久化并回填到当前进程。
- 桌面与 service 启动链路继续治理，收敛 Web / service / desktop 之间的启动边界与启动顺序，减少源码运行与打包运行的行为分叉。
- 项目内部继续推进长期维护向的重构治理：前端主入口、设置页、请求日志视图、Tauri 命令注册、service 生命周期、gateway protocol adapter、HTTP bridge、upstream attempt flow 等区域已进一步拆分模块边界，减少大文件与根层门面耦合。
- service / gateway 目录结构继续收敛，更多通配导入、跨层直连和超长门面清单已被显式依赖与分层模块替代，后续维护和协议回归定位成本更低。
- 发布链路继续收敛到 `release-all.yml` 单入口，并复用前端构建产物与协议回归基线，减少重复构建与发布时的协议回归风险。

### Changed

- 完善 SOCKS5 上游代理支持与归一化，并补充设置页中的代理协议提示文案。

## [0.1.5] - 2026-03-06

### Added
- 新增“按文件夹导入”：桌面端可直接选择目录，递归扫描其中 `.json` 文件并批量导入账号。
- 新增 OpenAI 上游代理配置与请求头收敛策略开关，可在设置页直接保存并即时生效。
- 补充 chat tools 命中探针脚本，便于本地验证工具调用是否真正命中与透传。

### Fixed
- 修复 `tool_calls` / `tools` 相关回归：补齐 chat 聚合路径中的工具调用保留、工具名缩短与响应还原链路，避免工具调用在 OpenAI 兼容返回、流式增量和适配转换中丢失或名称错乱。
- 完善 OpenClaw / Anthropic 兼容返回适配，确保工具调用、SSE 增量和非流式 JSON 响应都能按兼容格式正确还原。
- 请求日志追踪增强，补充原始路径、适配路径和更多上下文，便于定位 `/v1/chat/completions -> /v1/responses` 转发与协议适配问题。

### Changed
- 网关协议适配进一步对齐 Codex CLI：`/v1/chat/completions` 与 `/v1/responses` 两条链路统一收敛到 Codex `responses` 语义，上游流式/非流式行为与官方更接近，兼容 Cherry Studio 等客户端的 OpenAI 兼容调用。
- 设置页顶部常用配置改为统一的三列行布局，代理配置与其保持一致；同时支持关闭窗口后隐藏到系统托盘运行。
- 发布流程整合为单一一键多平台 workflow，并收敛桌面端产物形态；Windows 直接提供 portable exe，macOS 统一使用 DMG 分发。

## [0.1.4] - 2026-03-03

### Added
- 新增“一键移除不可用 Free 账号”：批量清理“不可用 + free 计划”账号，并返回扫描/跳过/删除统计。
- 新增“导出用户”：支持选择本地目录并按“一个账号一个 JSON 文件”导出。
- 导入兼容增强：支持 `tokens.*`、顶层 `*_token`、camelCase 字段（如 `accessToken` / `idToken` / `refreshToken`）自动识别。

### Fixed
- 兼容旧 service：前端导入前会自动归一化顶层 token 格式，避免旧版后端报 `missing field: tokens`。

### Changed
- 账号管理页操作区整合为单一“账号操作”下拉菜单，替代右侧多按钮堆叠，界面更简洁。
