# BPS 转发（实验性）

CodexManager 内置了独立实现的 Responses / ChatGPT Excel（Basispoints，BPS）协议适配器，不需要安装或启动外部桥接程序。此功能改变账号请求的上游入口，不保证模型质量提升，也不解除账号权限或额度限制。

## 使用

1. 管理员打开“OpenAI 账号池”，找到账号卡片底部或列表中的“BPS 转发”开关，默认关闭。
2. 点击开启后，先阅读“BPS 转发风险提示”：该功能不保证改善模型能力或避免“降智”，可能出现请求失败、功能不兼容及账号使用风险，使用风险由用户自行承担。弹窗会显示本次涉及的账号数量。点击“取消”保持原状态，不发起授权或提交开关变更。
3. 已有有效 BPS 授权的账号，点击“了解风险并开启”后启用。尚未授权的账号，点击“了解风险并授权”进入独立授权弹窗，再点击“开始 BPS 授权”，打开显示的授权页面，使用**当前所选账号**登录并输入设备验证码。服务会核对返回的 ChatGPT 账号，并在原凭据包含用户身份时一并核对，拒绝绑定不匹配的账号。
4. 从开关进入的授权在成功后继续开启 BPS；开关旁的钥匙图标是独立授权入口，只保存授权，不自动开启。
5. 批量操作时先勾选账号，再通过右上角“账号操作”开启或关闭 BPS。批量开启要求所有选中账号均已完成有效的独立授权；任何一个不满足时，整批保持原状态。符合条件的批次只弹出一次风险确认，确认后才提交该批账号的变更，取消不改变任何账号。
6. 关闭开关不需要风险确认，后续选中该账号的请求使用原有 Codex 上游。此操作不删除原账号或授权文件，也不替换原来的 Codex 凭据。

**已经导入或登录 Codex 的账号，首次使用 BPS 仍需单独授权。** 现有 Codex 凭据用于原 Codex 入口，不作为本功能的 BPS 授权使用；仍然使用同一个 ChatGPT 账号，无需创建新账号。BPS 授权与原 Codex 登录分别保存和维护。

**开始授权前，请先开启授权码登录：** 在 ChatGPT“设置 → 安全”中开启“设备代码登录”（授权码登录），再返回 CodexManager 开始 BPS 授权。工作区账号可能需要管理员启用。CodexManager 不会自动修改该设置，开启设备代码登录也不保证 BPS 使用权限。

桌面端与 Service 版 Web UI 使用同一服务端设置和授权流程。需要通过 CodexManager 网关接入；绕过网关的 OpenAI 账号直连不会经过此开关。

BPS 授权单独保存在数据库的 `account_bps_settings` 记录中；账号导入不会重置开关，删除账号时一并删除。列表和 RPC 只显示开关、授权是否在有效期内及到期时间，不返回访问令牌。界面显示已授权仅代表凭据已取得，并不代表真实生成已验证。首版不自动刷新 BPS 授权，到期后需要再次授权；Codex 的独立刷新流程保持原样。

## 请求行为

- 默认关闭。开启后，选中该账号的网关生成请求使用其独立 BPS 凭据、现有账号代理和网关超时设置，通过 WebSocket 访问 BPS。
- 支持 `/v1/responses`、兼容转换后的 `/v1/chat/completions`，以及客户端 WebSocket；返回继续使用已有 Responses / Chat 流式或非流式格式。
- 只要账号池中任一账号开启 BPS，新建客户端 WebSocket 连接就统一通过现有 HTTP 桥接层，再由账号路由选择上游。选中未开启 BPS 的账号时，仍使用原 Codex 上游；并非全部账号都转到 BPS。已有原生 WebSocket 会话在路由变化后可能需要重连。
- 保留请求模型，并显式传递归一化的推理档位：`low/high/medium` 保留，`xhigh/max/ultra` 等高档位映射为 `xhigh`，`none/minimal` 映射为 `low`，未指定时使用历史设置或 `medium`。响应保留上游报告的模型、推理和用量，不把请求档位伪装成上游验证结果。
- 原始 instructions 和完整对话历史进入适配请求。客户端 function/custom/namespace 工具通过 BPS 原生工具载体传递，结果还原为客户端工具调用；只有完整结束且验证通过的调用才交给客户端。工具实际执行仍在客户端。
- 单次只支持一个客户端工具调用。历史必须包含原始调用和结果；HTTP 请求仅给 `previous_response_id` 或 `item_reference` 时明确报错。客户端 WebSocket 的历史展开由已有桥接层处理。
- 默认请求上下文压缩阈值为 `200000`；可用 `context_management` 中合法的 compaction 配置覆盖。可见文本、HTTPS 图片及支持的加密历史状态会保留。
- BPS 错误单独处理，不把原 Codex 凭据判为失效或刷新成 BPS token。开启后发生错误不会静默回退原通道，已发送请求不自动重放。

## 兼容边界

- BPS 不提供原 Codex 托管搜索、文件搜索、代码解释器、图像生成等能力。`auto` 请求中的这些工具声明会省略，并在模型收到的协议说明和响应 `metadata.codexmanager_bps_omitted_tools` 中明确列出；强制要求这些工具时直接报错。普通客户端执行的工具不属于这个限制。
- 不支持内联图片、文件、音频、后台生成、受约束 JSON 输出，以及 `temperature`、`top_p`、`max_output_tokens`、`max_tool_calls`、`truncation` 等无法保留的参数；请求这些能力时返回明确错误，可关闭 BPS 后使用原通道。
- 不支持指定 Fast / Ultrafast / Flex 等服务等级。平台 Key 和请求中的服务等级应使用跟随请求或 Standard；仅 `auto/default` 可进入 BPS。
- 账号池的组别、Key 所有权、可选账号和模型路由边界继续生效。现有 Codex 用量显示不等同于 BPS 独立额度，授权成功也不等于该账号拥有每个请求模型的权限。
- BPS 是产品内部接口，模型权限与协议可能变化。验证应检查最终事件和任务结果；握手成功、返回 `200` 或请求设置 `xhigh` 均不能单独证明质量改善。

## 授权故障排查

如果浏览器授权页面提示 `deviceauth_disabled`，先检查设备代码登录是否被禁用。个人账号可在 ChatGPT 的“设置 → 安全”中检查设备代码登录设置；工作区账号可能需要管理员在工作区权限中启用。CodexManager 不会自动修改这些设置，请由你或工作区管理员自行决定。

确认设置允许设备代码登录后，回到 BPS 授权弹窗，点击“打开 BPS 授权页面”重试；如果验证码已过期，重新开始授权。允许设备代码登录只解决此类登录设置限制，不保证该账号具有 BPS 或所请求模型的使用权限。详见 [OpenAI 认证说明](https://learn.chatgpt.com/zh-Hans/docs/auth)。

## 验证

在账号卡片或列表的“更多账号操作”中选择“测试账号”，测试会跟随该账号的 BPS 开关：开启时测试 BPS，关闭时测试原 Codex 通道。BPS 模式仅支持文字模型测试，选择图片生成测试会明确报错，不会改走原通道。BPS 测试失败不会把原 Codex 登录判为失效，也不会借此修改原账号健康状态。请检查最终完成事件和实际文字结果，不能只依据连接成功判断生成成功。

本地回归使用模拟 OAuth / BPS 服务验证独立身份绑定、开关持久化、错误隔离、文本与工具转换、流式/非流式返回、取消及断线行为。真实上游生成需要用户完成独立 BPS 授权后验证，模拟测试不替代真实账号的权限检查。
