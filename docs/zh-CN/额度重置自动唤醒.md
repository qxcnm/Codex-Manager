# 额度重置自动唤醒

OpenAI 账号池默认开启此功能。系统记录账号已耗尽的标准 5 小时额度及上游返回的重置时间；时间到达后，主动向该账号发送简短预热消息，尽早开启下一轮使用窗口。预热成功后立即安排刷新该账号用量，减少等待常规额度轮询的时间。

## 使用方式

- 单个账号：在账号的更多操作菜单中选择“开启额度重置自动唤醒”或“关闭额度重置自动唤醒”。
- 批量操作：勾选账号，在“账号操作”菜单中选择“批量开启自动唤醒”或“批量关闭自动唤醒”。
- 表格和卡片均展示当前自动唤醒状态。开关存储在服务端，桌面端和 Web 共用，重启或重新导入账号后保留。

## 触发规则

- 服务运行期间，每 5 秒检查一次已记录的到期任务，重置时间后预留 5 秒缓冲，独立于用量轮询间隔和自定义预热 Cron；正常约在重置后 5–10 秒开始发送，大量账号同时到期时通过有界队列依次处理。
- 只针对已确认耗尽的标准 300 分钟窗口。没有有效重置时间、仅有周额度的账号，以及 Code Review / Spark 等附加额度，不会单独触发此功能。
- 账号被停用、不可用、封禁或缺少凭据时不发送；周额度仍耗尽时等待周额度重置。
- 每个账号的同一个重置周期只自动尝试一次，发送前将记录写入数据库。重复刷新、并发调度和服务重启不会重复触发该周期。已发起的预热请求及结果可在请求日志中查看，准备阶段错误查看服务日志；需要时可手动预热。
- 如果最新额度信息已表明新的 5 小时窗口开始使用，则跳过旧周期的待发消息。

自动唤醒会产生真实上游模型请求并消耗少量额度，默认使用低成本模型 `gpt-6-luna` 和预热消息 `hi`，并复用账号凭据与代理配置。额度恢复时间和请求是否成功以 OpenAI 上游响应为准。

## 接口

账号列表的 `resetWarmupEnabled` 为布尔值，默认 `true`。调用 `account/resetWarmup/update`，参数为 `{"accountIds":["账号 ID"],"enabled":false}`，可统一更新单个或多个账号，返回 `{"updated":1}`。空列表、非法参数或不存在的账号会报错；批量更新不会部分应用。
