# Журнал изменений

Этот файл фиксирует внешне заметные изменения CodexManager и служит единым источником истины по истории версий.
Формат основан на Keep a Changelog и слегка адаптирован под текущий репозиторий.

## [Unreleased]

## [0.6.3] - 2026-09-30

### Added

- В revision 10 каталога моделей добавлена builtin-модель `gpt-6.1-sol` с официальным описанием, уровнями reasoning и ценами input, cached input, cache write и output для короткого и длинного контекста. Custom-модели, пользовательские правки и tombstone удаления сохраняются.

### Changed

- Уплотнены и согласованы представление состояния в навигации рабочего стола, настройках, dashboard, режиме платформы и управлении моделями для поддерживаемых языков.

### Fixed

- Улучшены отслеживание доставки финального события streaming и диагностические bridge-логи: теперь различаются доставленный клиенту финальный event, незавершённый upstream и ошибка доставки клиенту.

## [0.6.2] - 2026-09-25

### Added

- В revision 9 каталога моделей добавлены `gpt-6-sol`, `gpt-6-luna`, `gpt-image-2.5-sunburst` и `gpt-image-2.5-flare`. Fresh-каталог теперь содержит 11 builtin-записей: 10 видимых моделей и скрытую `codex-auto-review`.

### Changed

- Из builtin-каталога удалены `gpt-5.4` и `gpt-5.4-mini`, выведенные из Codex со входом через ChatGPT 31 августа 2026 года, а также builtin `gpt-5.2`, deprecated для этого способа входа. Доступ через общий API key остаётся возможен через custom-модель. Revision 9 удаляет неизменённые builtin-записи и их стандартные routes account pool, но переводит в custom и сохраняет пользовательские правки, custom-цены или tiers, нестандартные routes и связи permission/API key.
- Варианты ограничения модели для free-account теперь строятся по текущему каталогу текстовых моделей. Сохранённые значения, которые больше не входят в список кандидатов, image-only значения и старые fallback нормализуются в `auto`; прогрев аккаунта и тест текста аккаунта используют fallback `gpt-6-luna`, а observation bridge использует `gpt-6-sol`, если модель не указана.
- Версия релиза повышена до `0.6.2`; синхронизированы workspace, frontend, Tauri desktop metadata и lock files.

### Fixed

- Исправлены разрешение команды pnpm и гонка запуска Next-прокси в desktop-разработке; скрытые страницы останавливают собственный polling и фоновые задачи, а account-test и SSE очищают слушатели в конечных состояниях.
- Исправлены границы жизненного цикла ресурсов, отмены запросов, метрик очередей и конкурентного доступа в service, gateway, account и usage путях, чтобы legacy synchronous bridge не оставался на рабочих production-маршрутах.
- Усилена автоматическая миграция старого SQLite каталога моделей: добавлены блокировка, online backup, preflight-проверки, обработка конфликтующих регистров slug и smoke check после миграции; при ошибке база восстанавливается из backup.
- В GHCR Release Compose добавлены необязательные Docker OTA profiles: обычная проверка ждёт подтверждения пользователя, а образы service/web обновляются автоматически только после явного включения `ota-auto`; фиксированные version tags остаются неизменными.

## [0.6.1] - 2026-09-24

### Added

- Для пула OpenAI-аккаунтов добавлен включённый по умолчанию прогрев после сброса квоты. При исчерпании 5-часового окна в сохранённое время сброса отправляется короткое сообщение и обновляется usage; доступны индивидуальный и массовый переключатели, попытки сохраняются по циклам, а отключённые аккаунты и ещё не восстановившиеся недельные квоты пропускаются.
- В Codex добавлен прямой режим aggregate API. Можно выбрать активную запись Codex или Compatible Responses с API-key и использовать её настроенные заголовки авторизации и User-Agent без прохождения через локальный gateway (#475).

### Changed

- Завершено production-укрепление асинхронного service и миграции хранилища на SeaORM: усилены transaction, shutdown и acceptance gates для удалённых аккаунтов, aggregate API, API keys, usage, logs и gateway paths.
- Унифицирован стиль status cards моделей. Если модели не выбраны, применяется весь каталог; при наличии выбора применяются только выбранные модели, одновременно синхронизируются цены и catalog metadata.
- Синхронизация цен сохраняет пользовательские цены, если модели не выбраны; для явно выбранных моделей внешняя цена может заменить пользовательскую, а невыбранные пользовательские модели не изменяются.
- Удаление моделей теперь физически удаляет записи. Для удалённых builtin-моделей сохраняется tombstone, поэтому startup seed не восстанавливает их.
- Версии workspace, frontend, Tauri desktop metadata и lock files повышены до `0.6.1`.

### Fixed

- Исправлена ситуация, когда успешный ответ aggregate API отмечался как 502 после разрыва соединения Windows-клиентом. Ошибки downstream `os error 10053/10054/10058` теперь считаются client disconnect (#479).
- Исправлены граничные случаи account, aggregate API, quota reset и candidate routing после асинхронной миграции service; усилены transaction rollback и проверка production configuration.

## [0.6.0] - 2026-09-05

### Fixed

- Исправлена ошибка обновления квоты: добавленный User-Agent в запросах подписки мог вызывать веб-защиту и последующую ошибку авторизации токена. Запросы подписки больше не задают User-Agent.
- Запросы квоты и обновление токена снова используют стандартный Codex User-Agent независимо от настроек шлюза, включая отдельные прокси аккаунтов.

### Changed

- Версия workspace, frontend, Tauri и lock-файлов повышена до `0.6.0`; сохранены существующие аккаунты и настройки.
- В `release-all` сборки сервисов и настольных приложений для пяти платформ выполняются параллельно. Кэш разделён по Cargo workspace; запуск с основной ветки для фиксированного коммита позволяет повторно использовать кэш между версиями. Состав артефактов сохранён.

## [0.5.7] - 2026-09-05

### Added

- В редактор аккаунта добавлен переключатель **Продолжать использовать аккаунт после исчерпания квоты**. Он сохраняется как `force_enabled`, по умолчанию выключен и оставляет аккаунт в пуле кандидатов шлюза для ручного управления квотой.
- В каталог моделей по умолчанию добавлена `gpt-6-astra`. Миграция данных revision 8 добавляет в новые и обновляемые базы официальные лимиты API и цены с учётом cache write, runtime-метаданные Codex и маршрут пула аккаунтов по умолчанию, сохраняя custom-модели с тем же slug и изменённые пользователем builtin-модели.
- На странице аккаунтов добавлен запоминаемый переключатель между таблицей и карточками. Администратор может получить upstream-модели для явно выбранного аккаунта ChatGPT с его credentials, идентификатором аккаунта и proxy, а затем выборочно привязать их к маршрутам пула аккаунтов каталога моделей V2 без ротации по пулу.
- В API keys, Responses HTTP, WebSocket и журнале запросов добавлены уровни обслуживания Standard и Ultrafast. Standard использует стандартную скорость upstream и записывается как `standard`, Fast преобразуется в `priority`, а Ultrafast передаётся без изменений; для совместимости по-прежнему принимается Flex, однако фактическая доступность зависит от модели и upstream.
- Добавлена настройка исходящего `User-Agent` шлюза: `gateway.user_agent` действует глобально, а `aggregate_apis.user_agent` отдельного подключения имеет приоритет для передачи aggregate route, получения списка моделей, probe и запросов баланса. Если оба значения не заданы, динамически формируется Codex-compatible `User-Agent` (#459).

### Changed

- Версия релиза повышена до `0.5.7`; синхронно обновлены workspace, frontend package, Tauri desktop metadata и lock files.

### Fixed

- Исправлено продолжение tool output в Responses WebSocket: повторные output одного tool call удаляются перед отправкой upstream, события connection preamble больше не расходуют попытку terminal recovery, а отсутствующий контекст tool call может ограниченно восстанавливаться между задачами (#458).
- Исправлено исчезновение usage Luna Reserve со страницы аккаунтов после последующих обновлений или временных пустых ответов; добавлена единая обработка дополнительных квот в форматах snake_case и camelCase.
- Исправлена граница маршрутизации Luna Reserve: аккаунты с доступной квотой Reserve попадают в пул Reserve только при явном запросе `gpt-reserve`. Обычные запросы `gpt-5.6-luna` продолжают использовать стандартный пул аккаунтов и не обходят исчерпанные окна 5 ч/7 д только из-за наличия Reserve; жесткие состояния авторизации и деактивации продолжают обрабатываться по прежним правилам.

## [0.5.6] - 2026-09-02

### Added

- Добавлена доступная только администратору функция **проверки аккаунта**, отправляющая реальные text- или image-model запросы upstream. Прогресс, результат и отмена передаются через Tauri events или Web SSE, изолированные непредсказуемым `testId`; статус аккаунта записывается через CAS по `status + updated_at`, поэтому устаревшая проверка не перезапишет новое состояние, а `banned`, `disabled` и `inactive` не восстанавливаются автоматически (#452).
- Добавлена стратегия **смешанной ротации с приоритетом агрегирующего API**. Сначала проверяются aggregate API, а переход к пулу аккаунтов выполняется только после отказа всех кандидатов без потребления запроса; модели только с aggregate-маршрутом не могут обходить привязанный route (#454).
- Добавлено получение моделей upstream из aggregate API и их выборочная привязка к route каталога моделей V2 без восстановления прежних source tables и автоматической цепочки привязки.

### Changed

- Версия релиза повышена до `0.5.6`; синхронно обновлены workspace, frontend package, Tauri desktop metadata и lock files.
- Улучшена маршрутизация prompt-cache/cache affinity: `prompt_cache_key` или корневой session ID разделяются по platform key, протоколу и модели, параллельные cold-start запросы атомарно сходятся на одной привязке, parent/child и streaming-запросы стабильно используют один аккаунт, а перепривязка выполняется только после успешного failover. В dashboard администратора также добавлен cache hit rate.

### Fixed

- Исправлены ложные ошибки проверки aggregate API у поставщиков со строгой валидацией клиента. Probe по умолчанию имитирует идентификаторы официального клиента Codex или использует настроенный `User-Agent`, не меняя обычную передачу route (#451).
- Исправлены lifecycle входа Codex через Device Code, отмена и гонка browser callback; синхронизированы authentication и поддержка WebSocket в managed gateway profile.
- Исправлены распознавание и маршрутизация нативных запросов Codex на генерацию изображений. Запросы расширения доходят до Codex image endpoint с необходимыми identity headers, а обычные OpenAI-compatible клиенты продолжают использовать compatibility adapter.
- Desktop updater теперь удаляет завершённые и устаревшие каталоги релизов, сохраняя ожидающий установки релиз и updater logs.

- Упрощён запуск и восстановление: навигация окна объединяется, окно показывается после готовности домашней страницы, сначала повторно используется уже инициализированный service, а повторные warmup-запросы удалены.

- Исправлено восстановление Responses WebSocket после раннего разрыва, лимита соединения, сбоя первого кадра, продолжения preamble, контекста `store=false` и изменения доступности аккаунта; после передачи существенного вывода запросы не дублируются скрыто.
- Исправлено переключение аккаунта для некоторых неуспешных ответов upstream и уточнена семантика маршрутизации default model group.

## [0.5.0] - 2026-07-23

### Added

- Добавлена авторизация аккаунта через Device Code для `chatgpt.com`: отображение и копирование кода, открытие страницы подтверждения, автоматический polling, отмена сессии и обработка истечения срока; браузерная авторизация и ручной разбор callback URL сохранены (#370).
- `/skills/` теперь разделяет установку Skills и установку плагинов Codex. Отдельные Skills можно устанавливать из встроенных и пользовательских GitHub-репозиториев, результатов skills.sh, ZIP-файлов и существующих каталогов, с фоновым обновлением источников и безопасным удалением; нативный Marketplace Codex сохраняет установку стандартных плагинов целиком, а `.system` Skills остаются read-only (#126).
- Добавлена модель `gpt-image-2` (снимок `gpt-image-2-2026-04-21`) как девятая builtin-модель и восьмая модель в обычном списке. Запись используется только для `/v1/images/generations` и `/v1/images/edits`, не публикуется как основная модель text, Chat Completions или direct Responses и содержит в метаданных каталога официальные ставки 8 / 2 / 30 USD за 1M image input / cached input / output tokens.

### Changed

- Версия релиза повышена до `0.5.0`; синхронно обновлены workspace, frontend package, Tauri desktop metadata и lock files.
- Устранены ошибки и предупреждения frontend lint, чтобы предрелизные проверки качества проходили чисто.

### Fixed

- Исправлена гибридная ротация, при которой модель только с маршрутом aggregate API сначала отправлялась в локальный пул аккаунтов. Такие модели теперь сразу используют привязанный aggregate API, модели с двумя маршрутами сохраняют приоритет аккаунтов с резервом через aggregate API, а модели только с пулом аккаунтов не переходят на непривязанный aggregate API (#381).
- Исправлено ненадёжное применение актуального размера окна предпросмотра трея в Windows. При создании и повторном использовании окна теперь заново задаются фиксированный логический размер `360 × 430` и ограничения, что устраняет обрезание содержимого и сохранение старого размера (#380).
- Исправлено переключение аккаунтов в Responses WebSocket, когда upstream сначала отправляет `response.created`, а затем сообщает об исчерпании квоты во вложенном событии `response.failed`. События жизненного цикла без содержимого теперь буферизуются, вложенные ошибки распознаются, исчерпанный аккаунт сразу помечается как limited, а текущий запрос незаметно повторяется на следующем доступном аккаунте.
- В Aggregate API добавлен универсальный тип provider `compatible`: один URL и ключ upstream могут обслуживать запросы Codex/OpenAI и native Claude по исходному пути без дублирования записей provider (#359).
- Исправлены ответы 401 для аккаунтов, импортированных только с `accessToken` из ChatGPT `/api/auth/session`. Пути HTTP, Responses WebSocket и account warmup теперь по мере необходимости регистрируют и сохраняют недостающие данные AgentIdentity, проверяют привязку аккаунта, используют AgentAssertion и принимают официальные nested-форматы AgentIdentity в snake_case и camelCase (#376).
- Исправлено отображение аккаунтов `/api/auth/session` как типовых placeholder-ов импортированных аккаунтов. Имя теперь извлекается из OpenAI profile в access token или данных session user; ручные имена не перезаписываются, а старые placeholder-метки обновляются.
- Тарификация GPT-5.6 Sol, Terra и Luna приведена к официальным ценам OpenAI API: для cached input применяется скидка 90%, а с порога 272K входных токенов включаются long-context ставки с 2x для input и 1,5x для output. Старые автоматические оценки мигрируют на официальные цены, пользовательские цены сохраняются.

## [0.4.4] - 2026-07-20

- service / gateway 目录结构继续收敛，更多通配导入、跨层直连和超长门面清单已被显式依赖与分层模块替代，后续维护和协议回归定位成本更低。
- 发布链路继续收敛到 `release-all.yml` 单入口，并复用前端构建产物与协议回归基线，减少重复构建与发布时的协议回归风险。
